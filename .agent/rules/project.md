Project: SE-INT-04 weekly-planning SaaS built from Launchbase.

Before coding:
- Read the root and folder AGENTS.md and README files; follow Launchbase conventions
  (uv run, autogenerated Alembic migrations, no enums in models, services flush and
  routers commit, npm run generate for the typed client).
- Where the brief and an AGENTS.md disagree, the brief wins. Tests are REQUIRED.
- Propose the plan first for broad or risky changes. Map each change to a test.

While coding:
- Enforce tenancy and roles in the API, never only in the UI.
- Platform staff means is_admin. The organization role is org_role. Keep the two
  distinct everywhere in code.
- AI output uses typed Pydantic output_type and goes to forms, never straight to the DB.
- Tests use TestModel/FunctionModel. No test may call Gemini.
- Never put secrets or customer data in source, prompts or reports.
- Never weaken, skip or delete a test to make a suite pass.
- Do not modify .agent/, scripts/check.sh or CI files without human review.

After coding:
- Run scripts/check.sh and report the exact commands and results.
- Do not claim success for any command that was not run or that failed.
- If blocked, say what is blocked and stop. Do not loop.
